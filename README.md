# 1TimeLink Self-Hosted (On-Prem) Deployment Guide

This directory contains configuration templates and guides for packaging and deploying 1TimeLink inside customer-managed environments (Single VPS) using separate containers for frontend, backend, and Slack proxy.

---

## 1. Directory Structure

* **`docker-compose.yml`**: Launches ingress (Caddy), frontend static site, application backend, and slack proxy.
* **`Caddyfile`**: Caddy reverse proxy routing configurations and client rate limits.
* **`Dockerfile.caddy`**: Builds Caddy with the custom rate-limiting plugin.
* **`slack-manifest.yaml`**: The Slack App Manifest configuration template.
* **`install.sh`**: Automated VPS installation and bootstrapping script.
* **`update.sh`**: Automated VPS application update script.
* **`vps-administration.md`**: Operations and runbook guide for system administrators managing the VPS stack.

---

## 2. Configuration Variables Reference

When deploying, the customer must inject these environment variables:

| Variable | Type | Description |
| :--- | :--- | :--- |
| `SPRING_DATASOURCE_URL` | Required | PostgreSQL connection URL (e.g. `jdbc:postgresql://db:5432/onetimelink`). |
| `SPRING_DATASOURCE_USERNAME` | Required | Database user. |
| `SPRING_DATASOURCE_PASSWORD` | Required | Database password. |
| `DB_ENCRYPTION_KEY` | Required | A 32-character key for database column encryption. |
| `APP_BASE_URL` | Required | The public domain of the application (e.g. `https://1tl.company.com`). |
| `DOMAIN` | Required (Compose) | The public domain name without protocol (e.g. `1tl.company.com`) for automatic Let's Encrypt SSL certificates. |
| `S3_ACCESS_KEY_ID` | Required | Cloud storage access key ID. |
| `S3_SECRET_ACCESS_KEY` | Required | Cloud storage secret key. |
| `S3_ENDPOINT` | Required | S3 endpoint URL (e.g. Cloudflare R2 endpoint). |
| `S3_BUCKET_NAME` | Required | S3 bucket name. |
| `LICENSE_KEY` | Required | The cryptographically signed license key generated by you. |
| `SLACK_PROXY_SECRET` | Optional | Shared token to authorize the companion Slack proxy. |
| `OTEL_SDK_DISABLED` | Optional | Set to `true` to disable OpenTelemetry monitoring. |

## 3. Deploying to a Single VPS (Docker Compose)

1. Copy the entire `1timelink-self-hosted/` folder to the target VPS.
2. Copy the example configuration template to `.env`:
   ```bash
   cp .env.example .env
   ```
3. Edit `.env` and fill in all required configuration variables (see Section 2 reference).
4. Run the installer script as root/sudo:
   ```bash
   sudo ./install.sh
   ```
   *Note: The script will read your `.env` settings to automatically configure database schemas and users, verify and format connection strings, and register Caddy routing domains.*
5. Log in as the newly created unprivileged app user:
   ```bash
   su - onetimelink
   ```
6. Navigate to the app directory, build the rate-limiting proxy, and deploy the stack:
   ```bash
   cd ~/app
   docker compose build
   docker stack deploy -c docker-compose.yml 1timelink
   ```

---

## 4. Updating the Application (Self-Hosted Clients)

To pull the latest software updates and apply them to the running stack without losing data:
1. Log in to the VPS as the unprivileged user:
   ```bash
   su - onetimelink
   ```
2. Navigate to the app directory and execute the automated update script:
   ```bash
   cd ~/app
   ./update.sh
   ```
